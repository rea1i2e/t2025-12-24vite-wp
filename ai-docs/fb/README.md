# 修正 FB（`ai-docs/fb/`）

案件の修正指示を **出所別・回次別** の Markdown に分けて置く。  
1ファイルに全案件分を溜めない（1回の指示で完結しない・添付が付く前提）。

## 種類（サブディレクトリは2つだけ）

| ディレクトリ | 出所 | 主な中身 |
|--------------|------|----------|
| [`qa/`](qa/) | 制作側（コーダー） | カンプ見比べ・`figma-qa-compare` の修正依頼文 |
| [`client/`](client/) | クライアント | 先方からの1回分の FB（**再現と変更が混在してよい**） |

**クライアント FB を「再現用ファイル」と「変更用ファイル」に分けない。**  
先方の1通・1シートには両方が入り混じることが多いため、**回次（連絡単位）で1ファイル**にし、項目ごとにタグを付ける。

| 項目タグ | 意味 |
|----------|------|
| `再現` | デザインカンプ／合意済み見た目への揃え |
| `変更` | 当初想定と違う仕様・文言・構成の変更 |
| `不明` | どちらか判断できない（要確認へ） |

制作側のカンプ差分だけを溜めるときは `qa/`（クライアント連絡と混ぜない）。

## 1回分の置き方

```text
ai-docs/fb/<qa|client>/
  YYYY-MM-DD-<短いラベル>.md     # 指示本文（チェックリスト）
  YYYY-MM-DD-<短いラベル>/       # 任意。スクショ・PDF・支給素材など添付
    *.png
    *.pdf
```

- md と添付フォルダは **同じステム名**（拡張子なしが一致）にする
- 雛形: `qa/_template.md` / `client/_template.md` をコピー
- 汎用ルールとして残す指摘だけ、別途ナレッジ `ai-code-feedback-stock` へ

## 役割分担

| 置き場 | 用途 |
|--------|------|
| **本ディレクトリ** | この案件の実装を直す指示と添付 |
| **`qa-reports/*.md`** | 初稿前 QA の差分レポート（転記元） |
| **`ai-docs/YYYY-MM-DD-revision-plan.md`** | `revision-intake-to-plan` の作業計画（関門後） |
| **ナレッジ `ai-code-feedback-stock`** | 横断ルール化（修正指示そのものではない） |

## ルール

1. 未対応の項目だけ着手する（対応済は触らない）
2. 指定したファイルを1ラリーでまとめて直す。項目ごとにチャットを分けない
3. 各項目のタグに従う:
   - `再現`: カンプ／正本デザインに揃える。なぜずれていたか原因をリサーチして md に書き、解明後は承認待ちせず修正する。修正後はブラウザで該当箇所を表示しスクショで自己確認（問題があれば再修正）
   - `変更`: 指示どおり変更する（カンプ再現の原因調査は不要）。必要ならブラウザで確認
   - `不明`: 直さず「要確認」へ残す
4. HTML/EJS/PHP のテキストコンテンツは自動生成しない（既存 or ユーザー提供を正）
5. 同名フォルダに添付があれば参照する
6. 直した項目はチェック済みにするか「対応済」へ移す
7. 判断が必要なもの・デザイン未確定のものは直さず「要確認」として残す

## 最も重要

今回、デザインカンプ通りに実装できなかった箇所は、なぜ実装できなかったのか、徹底的に原因をリサーチし、解明してください。

原因が解明した後に修正を行ってください。修正については、原因が確認できた段階で私の承認を得る必要はなく、修正は進めていただいて大丈夫です。

**すべての修正項目について、修正後に必ずブラウザで該当箇所を表示し、スクリーンショットを撮って、修正が正しく反映されていることを自分で確認してください。確認して問題があれば、再度修正してください。**

## ルール

1. 未対応の項目だけ着手する（対応済は触らない）
2. 各項目: 原因リサーチ → 解明を md の「原因」欄に書く → 修正 → ブラウザ確認（スクショ）
3. 原因が分かった項目は承認待ちにせず修正まで進める
4. ブラウザ確認のスクショは同名の添付フォルダ（無ければ作成）へ保存し、項目からリンクする
5. HTML/EJS/PHP のテキストコンテンツは自動生成しない（既存 or ユーザー提供を正）
6. 直した項目はチェック済みにするか「対応済」へ移す
7. 判断が必要なもの・デザイン未確定のものは直さず「要確認」として残す
8. Figma 正本は `ai-docs/figma-design-mapping.md`
